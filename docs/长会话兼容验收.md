# 长会话兼容验收

升级 Server 或 Web 时，用原版 Runtime 和新版 Runtime 分别读取同一份已落盘的测试数据。兼容矩阵从 v0.8.0 开始。每个待测实例都需要能用测试账号 `acct-1` 通过 Server 访问测试 Agent `local-heavy-history`。

## 准备数据

使用 SDK 的 uv 测试环境运行下列脚本。设置 `KSADK_TEST_POSTGRES_DSN` 指向专用测试库，`KSADK_HISTORY_FIXTURE_NAMESPACE` 指向新命名空间，并让各 Runtime 的 PostgreSQL Session Service 使用同一个库和命名空间。脚本会在已有同名测试会话时退出。

```sh
python e2e/fixtures/seed-released-runtime-history.py
```

A 包含一个 17,328 事件调用。B 包含 120 条编号消息及工具记录。C 同时跨越 8,192 事件和 16 MiB 两个原始预算，包含时间戳回拨、跨页模型回复和推理、两个并行同名工具及逆序返回的一成功一失败结果。D 包含需要按需展开的大工具结果。

## 核对持久化数据和浏览器

假设本机不同端口分别通向使用不同 SDK 的测试实例。在 Web 仓库中执行：

```sh
python e2e/fixtures/check-released-history-pages.py \
  --facade v0.8.0=http://127.0.0.1:20200 \
  --facade current=http://127.0.0.1:20209 --max-page-p95-ms 1000 --verify-appends

KSADK_HISTORY_FACADES='v0.8.0=http://127.0.0.1:20200,current=http://127.0.0.1:20209' \
KSADK_HISTORY_FIRST_PAINT_MS=2500 KSADK_HISTORY_OLDER_P95_MS=1000 \
  npx playwright test -c playwright.released-runtime-history.config.mjs
```

按相同格式追加发布标签。接口检查将每页条目的序号、身份、类型、作者、时间戳、正文与元数据逐项与 PostgreSQL 对照，同时覆盖旧页重试和向前补读。加上 `--verify-appends` 后，每个目标还会创建一个独立会话，在关闭 HTTP 连接后追加 165 条事件，再验证旧快照与重连补读分别覆盖各自的区间，结束时删除测试会话。Chromium 通过实际页面操作翻页，核对消息顺序、工具参数和结果，以及翻页失败后已显示内容和游标的保留。首屏计时从点击打开会话到最新消息可见，翻页计时到新页状态应用完毕。测试记录首屏及翻页分位数，便于与相同环境下的后续版本比较。
