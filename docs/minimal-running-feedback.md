# 聊天末尾运行提示

实现基线：`origin/main` 的 `bcc5e7bc5aa3429aac0a67dea1ed1f171a9274c3`。
分支：`codex/chat-running-feedback`。

## 展示行为

当前会话运行期间，在全部消息后保留一行小圆点和动态文字。
没有计时器、进度百分比、节点面板或新增操作按钮。
现有思考、工具参数、工具结果、审批和停止入口继续由原组件展示。

文案来自当前运行的真实状态：提交、思考、生成回复、等待工具返回、等待确认、同步或重连。
没有新增事件时维持当前提示，不虚构阶段变化，也不因工具长时间没有输出而自行判定完成。
等待用户确认时停止动画；系统开启减少动态效果时关闭动画。
收到完成、失败或停止状态后收起提示；错误仍通过已有错误展示处理。

## 会话与刷新恢复

- 提示跟随当前 session 的运行状态。新建空白会话不继承后台会话的提示。
- 切回仍在运行的会话时，先显示同步状态，再沿用现有历史读取和事件续订。
- 已有原生运行引擎仍持有该 run 时，继续复用原引擎，不再打开第二条恢复订阅。
- 整页刷新后通过后端 `ActiveInvocationId` / `ActiveRunStatus` 和持久化事件恢复，恢复动作只读取和订阅，不重新执行请求。
- 离开期间已经完成时，匹配同一 run 的后端终态或根运行历史终态会清理旧的运行标记；其他 run 或子作用域的终态不能清理当前运行。
- 已知运行的状态查询失败时显示“正在确认任务状态…”，不凭旧快照宣告完成。

恢复依赖现有 `RunLifecycle.Enabled`、`RunLifecycle.Resume` 能力及后端事件持久化。
客户端提示不能使一个本身不支持脱离浏览器执行的后端获得后台执行能力。
首次提交尚未取得后端运行身份时刷新，仍遵循已有未知投递恢复规则，不自动重发。
未发送输入和本地队列的刷新恢复不在本次新增范围内。

## 兼容范围

本次只调整共享 Web 展示与现有恢复状态的核对，不新增 API、事件协议或包版本。
旧 AG-UI 专用客户端、传输、审批与取消逻辑没有改动。
新的被动末尾提示由共享消息列表统一显示。
SDK 和服务端不需要为这个提示升级接口；集成方仍需按现有发布流程采用新的 Web 构建。
